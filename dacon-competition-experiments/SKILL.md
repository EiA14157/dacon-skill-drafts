# 경진대회 실험 설계와 논문 기록

1. 공식 대회 페이지에서 입력·레이블·출력, 지표와 점수 방향, 공개/비공개 리더보드, 제출 형식, 외부 데이터·가중치·AI 도구 허용 범위를 확인한다. 링크와 확인 날짜를 적고 접근이 막힌 항목을 표시한다.
2. 샘플 단위와 테스트 환경에 따라 고정 분할을 정한다. 환자·제품·배치 등 동일 개체는 함께 묶고, 미래 예측은 시간순으로 나눈다. 분할 ID, seed, 클래스 수와 분포를 저장한다. 그룹 수나 희소 클래스 때문에 폴드가 성립하지 않으면 가능한 분할 수부터 확인한다.
3. 단순 기준과 실전 베이스라인을 만든다. 모델마다 데이터 규모·레이블·지표와 연결된 가설과 반증 조건을 먼저 적는다. 같은 분할과 지표에서 한 변수씩 바꾸고 코드 실행 가능 여부, 장치, 실행 시간, 설정, 아티팩트 경로를 남긴다.
4. 학습·검증·샘플 제출 생성을 한 번 통과시킨 뒤 본 실험을 실행한다. 성공한 실행의 폴드별 점수와 평균·편차, 주요 오류 슬라이스, 비용을 기록한다. 실험 실패는 원인과 다음 조치까지 기록한다. 작은 점수 차이는 폴드별 일관성을 확인하고 필요시 같은 분할에서 seed를 추가한다.
5. 수상 코드에 나온 기법은 공식 규칙과 현재 데이터에 맞는지 확인한 뒤 작은 단위로 재현한다. 리더보드와 로컬 검증이 어긋나면 제출 반복에 앞서 분할, 표본 차이, 지표 구현을 점검한다. 제출 파일은 ID·순서·범위·결측·열을 검증한다.
6. 논문 초안에는 문제, 방법, 실험 조건, 실제 수치, 오류 분석, 한계를 남기고 매 실행 후 갱신한다. 실행이 불가능하면 재현 명령과 정확한 제약을 남겨 실험 상태를 미실행으로 표시한다.

실험 기록 필드는 `run_id | 가설 | 변경 변수 | split_id | seed | 모델·설정 | 폴드별 공식 지표 | 비용 | 상태 | 오류·해석 | 다음 실험`으로 유지한다.

## 주제 출처

[DACON 랭커특강 목록](https://dacon.io/hackathon#videoSection)에서 최신순으로 표시된 42개 카드 중 7·8·11·19–21·24·25·29–33·39–42번. ML·DL 입문과 직무, 대회 참여·기획·성장, 상위권 전략, 우승 코드 리뷰와 랭커 사례. 공개 제목을 바탕으로 적용 절차를 작성했다.
